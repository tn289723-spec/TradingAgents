# TradingAgents-TW Mobile-First Web (read-only)

Static UI at `web/index.html`. The evidence-readiness panel consumes the serialized `DashboardProjection` v1 contract from `render_dashboard_projection_json(report)`. A separate read-only market-data panel consumes the generated `market-sources.json` snapshot; it displays official RAW evidence and never computes State or a trading signal.

## Local use
```sh
node --test web/dashboard.test.mjs
python -m http.server 8080 --directory web
```
Open the local HTTP server in a browser. With no `web/projection.json`, the screen remains **BLOCKED / no data**. You may load an actual v1 projection JSON through the file picker. A manually imported JSON is schema-checked but **not cryptographically authenticated**.

## Deployment
GitHub Pages workflow captures official TWSE, TPEx, and TDCC sources on weekdays after market close, packages a bounded normalized snapshot as same-origin `market-sources.json`, and deploys the static dashboard. The snapshot includes source URLs, observation times, response hashes, board/session dates, and per-symbol source records. Its status stays `RAW_UNVERIFIED`; it does not pass the PIT release gate and cannot create scores. The browser blocks snapshots older than 72 hours. `projection.json` remains separately gated and is not generated by this workflow.

The page intentionally contains **no** default `projection.json` or embedded sample prices. A missing, invalid, future-version or contradictory projection shows no scores. The UI cannot independently certify historical PIT completeness, verify signed archive attestations or reconstruct upstream Truth/State; those gates must run before publishing. A green light only means the upstream report's **evidence-readiness gate**, not a trading signal or a claim of historical PIT certification. The official market-data panel is independently marked RAW and unverified.

Do not put the local file-picker content into analytics, localStorage, or network upload. The current implementation does not persist the selected file.

## Acceptance
```sh
node --test web/dashboard.test.mjs
pytest
```
CI runs both Python matrices and the Node 22 dashboard smoke tests. Production hosting and genuine signed PIT capture remain separate release gates.

## GitHub Pages alternative (no Cloudflare project creation)
A deployment workflow at `.github/workflows/pages.yml` builds the audited, read-only static client plus the latest normalized official source snapshot. It does **not** publish synthetic or user-uploaded `projection.json`, secrets, or test fixtures.

The repository administrator must enable **Settings → Pages → Build and deployment → Source: GitHub Actions** once, if Pages is not yet enabled. The workflow then runs on changes to `web/**` or the Pages workflow on `main`, or manually via `workflow_dispatch`. The expected URL shape is `https://tn289723-spec.github.io/TradingAgents/` **only after** a successful deployment and independent HTTP reachability check; do not claim it is live from workflow creation alone.

The official market-data panel requires a successful Pages capture/deploy run and displays the snapshot's observation time. The score/evidence-readiness panel remains **BLOCKED / no trusted projection** until a separately authorized, independently verified PIT pipeline publishes a valid same-origin `projection.json`. Manual JSON import is for local inspection, not verified live market data. The release gate remains open until HTTPS and deployment success are observed.
